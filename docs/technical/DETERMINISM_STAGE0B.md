# 阶段 0B · 炮台发射 FPS 解耦

基线为 #20 合并后的 8bb8ad5。发射仍使用渲染回调，保留原高 FPS 条件下的脉冲节拍、单炮队列倍率、总队列倍率与预算。实际 FPS 继续用于 HUD 与视觉降档。

## Windows · Godot 4.7.1

- 旧代码对照：在隔离工作树里，仅替换两个 FPS 读取点。种子 12345，记录 tick 543 后分别提供 1 和 120。首次分歧仍在 tick 544，阵营 2 的计时分别为 0.1193 秒和 0.0153 秒。生产分支没有注入代码。
- 修复后用 60 Hz 固定步长比较 15 秒。tick 544 实际 FPS 为 2 和 398，0–900 个 tick 的模拟摘要及结束信息一致。
- 种子 12345（300 秒）、23456（90 秒）、34567（45 秒）各独立 3 次，9 对组内比较均一致。300 秒组到 tick 18000，全部达到时间上限。
- 真实窗口分别实测 15 与 60 FPS。五组队列输入下，发射间隔与每帧预算分别同为 [0.032 秒, 3]、[0.03456 秒, 3]、[0.038016 秒, 2]、[0.042163 秒, 1]、[0.049971 秒, 1]。
- 真实窗口完整轨迹在 tick 0 就不同。15 秒窗口内，60 FPS 条件记录 902 次渲染回调，15 FPS 条件为 227 次，两边各 914 次物理回调。相同的发射规则与相同的完整战局是两项不同验收。
- 现役 12 个 runner 均通过。日志检查同时筛查了脚本错误、运行错误和失败标记。
