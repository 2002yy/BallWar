# P1 弹珠互撞原型 / Bullet Collision Prototype

Date: 2026-11-28
Status: 原型数据，尚未合并；互撞默认关闭，经典规则未变
Baseline: `main@cc54c3c`（PR #32 设计文档 + PR #33 P0 已合并）
Scope: 只做 C1（不同阵营普通弹相互抵消）与空间分桶；不含特殊弹种、地图、存档字段

## 1. 开关与执行顺序

| 项目 | 值 |
|---|---|
| 开关 | 环境变量 `BALLWAR_BULLET_COLLISION=1`，默认关闭 |
| 桶尺寸 | `cell_size × N`，默认 N=1（40×40 为 13px），`BALLWAR_COLLISION_BUCKET_CELLS` 可改 |
| 顺序实验 | `BALLWAR_COLLISION_ORDER=reverse`，只用于偏差对照 |
| 分步接口 | `Bullet.advance_tick()` / `BulletPool.step_controlled()` / `Bullet.resolve_tick()` |

开启后所有炮弹由 `BulletPool._physics_process` 统一推进，单个炮弹不再自己完整执行：

```
全部 advance_tick（移动、边界反弹、记录待结算格/炮台）
→ 分桶 + 互撞（命中同时收集，再统一回收）
→ 按固定顺序 resolve_tick（炮台伤害 → 领土占领 → 回收）
```

关闭时 `Bullet._physics_process` 仍按原路径执行 `advance_tick + resolve_tick`，与旧代码逐 tick 等价（见 §2）。

## 2. 经典行为未变的证据

| 对照 | 结果 |
|---|---|
| 互撞关闭，种子 12345，60s | 与 P0 之前基线 `trace_before.tsv` **ticks 0..3600 完全一致** |
| 互撞开启，种子 12345，60s | 与关闭状态逐 tick 一致（该时段无跨阵营相遇） |
| 互撞开启，密火 120s 重跑 | 两次运行 **ticks 0..7200 完全一致**（碰撞路径本身可复现） |

## 3. 性能：合成分布（离线微基准）

|---|---|---|---|---|---|---|---|---|---|---|
| 600 | 均匀 | 497 | 4 | 1,009 | 768 | 249 | 0.68ms | 1.83 / 2.77ms | 0.81ms | 3.31 / 4.64 / 4.82ms |
| 600 | 战线 | 68 | 15 | 15,820 | 11,908 | 600 | 0.58ms | 15.24 / 17.49ms | 2.10ms | 18.23 / 21.48 / 29.36ms |
| 600 | 聚集 | 41 | 30 | 40,153 | 30,156 | 600 | 0.63ms | 35.25 / 37.72ms | 2.36ms | 38.55 / 40.81 / 42.17ms |
| 1800 | 均匀 | 1,064 | 7 | 8,681 | 6,548 | 1,416 | 2.93ms | 11.79 / 14.09ms | 5.51ms | 20.37 / 22.32 / 30.09ms |
| 1800 | 战线 | 68 | 39 | 141,578 | 106,199 | 1,800 | 2.07ms | 136.02 / 151.54ms | 7.72ms | 145.44 / 166.68 / 171.90ms |
| 1800 | 聚集 | 42 | 75 | 347,333 | 260,833 | 1,800 | 2.25ms | 321.59 / 349.15ms | 7.45ms | 331.24 / 358.91 / 393.00ms |
| 2800 | 均匀 | 1,330 | 8 | 21,119 | 15,894 | 2,512 | 4.44ms | 28.48 / 32.41ms | 10.93ms | 44.23 / 49.56 / 66.65ms |
| 2800 | 战线 | 68 | 56 | 337,825 | 253,705 | 2,800 | 3.77ms | 353.39 / 424.69ms | 12.55ms | 370.02 / 442.15 / 444.56ms |
| 2800 | 聚集 | 42 | 110 | 846,796 | 634,956 | 2,800 | 3.62ms | 815.47 / 869.99ms | 12.13ms | 831.59 / 886.11 / 907.30ms |
| 1800 | 均匀（桶=2格） | 398 | 12 | 33,927 | 25,495 | 1,422 | 2.20ms | 33.58 / 36.22ms | 5.77ms | 41.56 / 44.37 / 46.52ms |

结论：

1. **均匀稀疏分布可以跑**，1800 发仍在 16.6ms 预算内（20ms 含一次 1416 发的批量回收；回收在真实对局里不会每 tick 发生）。
2. **战线/聚集分布不可接受**。1800 发挤在一条 16px 战线上，检测一项就要 136ms。分桶没有救回这种情况，因为同一桶里有 39–110 发。
3. **桶加大更慢**：1800 均匀从 1 格桶换成 2 格桶，检测从 11.8ms 涨到 33.6ms（候选对 6,548 → 25,495）。1 格桶是对的。
4. 成本构成：建桶 ≈ 1.5µs/发，距离检测 ≈ 1.3–1.4µs/对，回收 ≈ 4–5µs/发。都是 GDScript 方法调用的量级。

这些是**对抗性密度**：真实对局 40×40 默认火力下峰值只有 **91** 发，密火实验峰值 **230** 发。6000 发在本机当前玩法里根本到不了，所以 6000 档没有测，只记录为"需要换成紧凑数组或 GDExtension 再谈"。

## 4. 性能：真实窗口 A/B（1120×720，vsync 关，画质高）

同一场景：四仓塞满 + 每 0.5s 四炮台强制齐射 120 发，32 秒，碰撞开/关各一次。

| 指标 | 关闭 | 开启 | 增量 |
|---|---|---|---|
| 平均帧时间 | 7.13ms | 7.76ms | +0.63ms |
| p95 | 12.67ms | 13.80ms | +1.13ms |
| p99 | 20.24ms | 22.70ms | +2.46ms |
| 采样帧数 | 4,179 | 3,845 | — |
| 画面活跃弹 | 231 | 268 | — |

结论：在真实玩法密度（200–300 发）下，互撞开销在 1ms 量级，可以接受；整帧 p99 20ms+ 是场景本身（600 段拖尾 + 4 仓 + 界面）的成本，不是互撞引入的。

## 5. 玩法对照（密火 120s，同种子）

强制四炮台每 1s 齐射 40 发，制造高密度弹幕，其余规则不变。

| 指标 | 互撞关闭 | 互撞开启 |
|---|---|---|
| 生成总数 | 9,568 | 9,568 |
| 峰值活跃 | 230 | 230 |
| 被互撞移除 | 0 | 3,214（33.6% 的生成量） |
| 领先易手 | 113 | 83 |
| 最终领土（蓝/红/绿/黄） | 392 / 396 / 410 / 402 | 400 / 387 / 377 / 436 |
| 首座炮台摧毁 | 无（120s 内） | 无（120s 内） |

观察：

- 互撞确实吃掉了约三分之一的弹幕，并把领先易手从 113 次压到 83 次 —— **战局更稳，但也更慢**，这正是设计文档里预警的僵持风险。
- 120s 内双方都没有打掉炮台：炮弹在越过边境的第一格就消失了，纵深打击仍然只能靠特殊弹种。
- 默认火力（不强制齐射）下 300s 内 **一次跨阵营相遇都没有**（`distance_checks=0`，`hit_bullets=0`）。四阵营轮流开火、各打各的象限，弹幕在空间上几乎不重叠 —— **C1 在当前默认节奏下没有玩法影响**。这是 P1 最重要的发现：互撞的价值取决于火力密度和交错程度，而不是碰撞代码本身。

## 6. 顺序偏差

同一密火场景，`resolve_tick` 正序 vs 逆序：

| 指标 | 正序 | 逆序 |
|---|---|---|
| 领先易手 | 83 | 104 |
| 被互撞移除 | 3,214 | 3,224 |
| 最终领土 | 400 / 387 / 377 / 436 | 400 / 386 / 379 / 435 |

终局领土只差 1–2 格，没有系统性阵营优势；但过程（领先易手次数）差 25%，说明结算顺序会改变中盘走向。结论：**顺序必须冻结为一个固定规则**（当前是炮弹池数组顺序），不能按帧或按随机数改变，否则同种子不可复现。

## 7. 正确性探针

`tools/tests/collision_benchmark.gd` 自带 5 项，全部通过：

| 探针 | 结果 |
|---|---|
| 跨桶：相距 1px、分属相邻桶的两发 | 命中 |
| 去重：4 发同桶，应有 6 对且只算一次 | 6 对、4 发全部移除 |
| 扫掠：1800px/s 对穿，端点都在接触圈外 | 命中（端点检测会漏） |
| 同阵营：4px 内两发 | 穿过，不命中 |
| 回收状态：上一颗特殊弹的属性残留 | 见 `IntegrationTestRunner`，6 项断言 |

搜索半径会按 `2 × 最大单帧位移 / 桶尺寸` 自动放大：普通速度恒为 1（3×3 邻域），高速时扩大，避免跨桶漏判。

## 8. 已知边界

| 边界 | 说明 |
|---|---|
| 密度上限 | 互撞开启后，同屏存活弹数受"相遇即抵消"约束；1800 发挤在一个屏幕里在物理上无法稳定存在 |
| 6000 档 | 未测。要让 6000 发可用，需要紧凑数组/批量遍历，先把 ~1.3µs/对降下来，而不是降画质 |
| 顺序 | 固定为炮弹池数组顺序；若要"生成顺序"，需要新增序号索引（当前有 `spawn_serial` 但没有用于排序） |
| 未统一时钟 | 本原型用 `_physics_process` + `advance_tick`，与 #25 的固定模拟时钟/#26 的战况工具尚未合并，合并前必须统一 |
| 未接 UI | 没有互撞开关界面，只有环境变量 |
| 未入存档 | 开关与碰撞状态不入档；读档后按启动时的环境变量决定 |

## 9. 复现

```bash
# 经典基线（互撞关）：应与改动前逐 tick 一致
BALLWAR_MATCH_SEED=12345 bash scripts/tests/determinism_probe.sh base 60

# 密火对照（互撞开/关）
BALLWAR_EXPERIMENT_FIRE=1 BALLWAR_BULLET_COLLISION=1 \
  bash scripts/tests/determinism_probe.sh dense 120

# 离线性能矩阵 + 正确性探针
godot --headless --path . --script res://tools/tests/collision_benchmark.gd

# 真实窗口截图与帧时间
CAPTURE_FORCE_FIRE=1 CAPTURE_FORCE_FIRE_COUNT=120 BALLWAR_BULLET_COLLISION=1 \
  godot --path . --resolution 1120x720 --script res://tools/capture/capture_battle.gd
```
